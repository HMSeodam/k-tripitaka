# 신한글대장경 — 한문 불전 원문·한국어 대조 열람기

CBETA·SAT·KABC에서 가져온 한문 원문과 선생님의 한국어 번역을 **대장경 위치표지**(`[0287c01]`) 단위로 묶어 읽고 검색하는 정적 웹앱입니다.
GitHub Pages에 그대로 올라가고, 같은 코드가 모바일에서도 앱처럼 동작합니다.

**→ [사이트 바로가기](https://hmseodam.github.io/k-tripitaka/)**

## 1. 자료를 추가하는 방법

**권장: 원본을 그대로 올리면 GitHub가 알아서 변환합니다.**

```
sources/<문헌id>/원문.txt      ← CBETA·SAT·KABC 복사본 (선택)
sources/<문헌id>/번역.docx     ← AI 번역 결과 docx (선택)
```

이 두 파일을 넣고 커밋해서 밀기만 하면 끝입니다. `.github/workflows/build.yml`이
`ingest.py`를 돌려 `data/works/<문헌id>.json`과 `data/manifest.json`을 만들고,
그 결과를 저장소에 되돌려 커밋한 뒤 Pages에 배포합니다. **둘 중 하나만 있어도 됩니다.**

- 원문만 → 원문 검색·열람만 제공
- 번역 docx만 → docx 안의 한문 원문을 뽑아 대조본 생성

`tools/registry.json`에 서지를 적어 두지 않아도 목록에는 실립니다(「미분류 · 서지 미기재」로
표시). 나중에 항목을 채우면 그때부터 정식 서지와 대장경 정렬이 적용됩니다.

**직접 만든 JSON을 넣는 경우**도 됩니다. `data/works/`에 파일을 떨구면 `rebuild_manifest.py`가
목록을 다시 만들어 자동으로 실어 줍니다. 다만 형식은 아래 「JSON 한 단위의 모양」을 지켜야 합니다.

**손으로 돌릴 때**는 이렇습니다.

```bash
pip install python-docx
python3 tools/ingest.py            # 원본 → 대조 JSON + 목록
python3 tools/rebuild_manifest.py  # 목록만 다시 만들 때
```

### 자동화가 하는 일과 하지 않는 일

| 하는 일 | 하지 않는 일 |
|---|---|
| 원문·번역 정렬, 분권, 해제 분리 | 서지(대장경 번호·찬자) 판정 |
| 목록·통계·정렬 갱신 | 번역 품질 검증 |
| Pages 배포 | 판본 대조 |

서지는 사람이 `registry.json`에 적어야 합니다. 자동 편입된 문헌은 목록에서
「서지 미기재」로 눈에 띄게 표시되니 빠뜨릴 일은 없습니다.

### 분권과 해제는 자동으로 갈라집니다

번역 docx의 표제 계층을 읽어 **권/장 단위로 나눕니다.** 열람 화면은 한 번에 한 권만 그리므로 스크롤이 늘어지지 않습니다. 상단 드롭다운으로 권을 옮기고, 검색 결과에서 어느 대목을 누르면 그 대목이 든 권이 알아서 열립니다.

표제는 네 갈래로 가릅니다.

| 갈래 | 예 | 처리 |
|---|---|---|
| 해제 | `A. 문헌 정보`, `편집·번역 안내`, `핵심 용어표`, `검증 보고` | 본문에서 빼내 서지 패널의 '해제'로 |
| 권·절 | `권상`, `상권 제2분권`, `제3 전역 傳譯第三`, `【科層】K1 觀因緣門第一` | 분권·소제목으로 |
| 단위 | `문단 001 · [1089a06]`, `001. T45 0613a08` | 단위 표지로 |
| 주석 | `주`, `제1문 주` | 이하 문단을 각주로 |

원문 TXT만 있는 문헌은 원문 안의 권 표제(`大乘起信論䟽卷第一` 등)로 분권합니다.

단위가 60개 미만이면 나누지 않고 한 화면에 둡니다. 절 표제는 본문 사이 소제목으로만 씁니다.

### 번역 docx는 어떤 형식이어야 하나

`tools/번역docx-작성규격.md`에 정리해 두었습니다. GPT에 번역을 시킬 때 그 파일 끝의
「GPT에 붙일 문구」를 함께 주시면, 나온 docx를 손대지 않고 그대로 넣을 수 있습니다.

요점만 추리면 이렇습니다.

1. 원문 한 문단, 번역 한 문단을 번갈아 배치 — **한 문단에 섞지 않기**
2. 위치표지(`[0287c01]`) 남기기
3. 분권·과단을 제목 스타일로
4. 편집 안내·용어표·검증 보고는 `A. 문헌 정보`, `편집·번역 안내` 같은 제목으로 분리
5. 각주는 `주` 제목 아래에

### 정렬은 어떻게 되는가

번역 docx는 만들 때마다 스타일 이름이 달라집니다(`Source Text`, `Chinese Source`, `대조 원문`, 그냥 `Normal`…). 그래서 파이프라인은 **스타일을 보지 않습니다.** 대신

1. **위치표지 일치** — CBETA·SAT·KABC가 공유하는 유일한 안정 좌표
2. **한문 앞머리 지문 대조** — 위치표지가 지워진 docx용
3. **원문 전문 부분문자열 탐색** — docx가 원문을 더 잘게 쪼갠 경우

세 단계를 차례로 시도합니다. 한글/한자 **문자 비율**로 원문 단락과 번역 단락을 가르므로, 앞으로 어떤 형식의 번역 docx가 들어와도 손댈 곳이 없습니다. 각주·교감 메모는 따로 모아 `nt`에 담습니다.

## 2. 화면 구성

- **문헌 목록** — 대장경 순서(대정장 → 만신찬속장 → 만자속장, 책·경 번호순)로 정렬. 한문 원제와 한글 제목, 대장경 소재를 함께 보여 줍니다
- **대조 열람** — 좌우 대조가 기본입니다(위아래로 바꿀 수 있고, 좁은 화면에서는 자동으로 접힙니다). 원문만/번역만 전환, 서지·용어표·해제
- **찾기** — 원문·번역 동시 검색, 문헌별 필터, 앞뒤 문맥(KWIC) 표시

왼쪽 세로줄의 **행표 레일**이 이 도구의 중심입니다. 좌표를 누르면 그 대목의 주소가 복사되어, 논문 각주나 메일에 `#/w/gisin-yaksul/1092c23` 형태로 바로 붙일 수 있습니다.

검색은 판본 간 흔들리는 글자를 자동으로 접습니다(眞·真, 衆·眾, 淨·凈). 접는 글자는 `assets/js/search.worker.js`의 `VAR` 표에 추가하면 늘어납니다.

## 4. 배포

올리는 절차는 `깃허브-올리는법.md`에 따로 정리해 두었습니다.


### GitHub Pages

```bash
git init && git add -A && git commit -m "신한글대장경 초판"
git remote add origin git@github.com:<계정>/<저장소>.git
git push -u origin main
```

저장소 Settings → Pages → Source를 `main` 브랜치 루트로 지정하면 끝입니다. `.nojekyll`이 들어 있어 Jekyll이 파일을 건드리지 않습니다.

### 모바일

별도 앱이 필요 없습니다. 브라우저에서 열고 "홈 화면에 추가"를 누르면 전체화면으로 뜨고, 한 번 연 문헌은 서비스워커가 캐시해 두어 지하철에서도 읽힙니다.

## 4. 서비스로 옮길 때

지금 구조는 **말뭉치 30MB 안팎까지** 문제없이 버팁니다. 그 이상으로 커지면 검색만 서버로 넘기면 됩니다. 교체 지점은 `assets/js/search.worker.js` 한 곳입니다.

| 단계 | 규모 | 검색 방식 |
|---|---|---|
| 지금 | ~10종 | 브라우저 워커 선형 탐색 |
| 다음 | ~100종 | 빌드 때 이분(bigram) 역색인 생성 → 워커가 필요한 조각만 내려받기 |
| 본서비스 | CBETA 전량 | SQLite FTS5 또는 Meilisearch 백엔드 + `/api/search` |

데이터 형식(`data/works/*.json`)은 세 단계에서 그대로 씁니다. 지금 쌓는 자료가 나중에 버려지지 않습니다.

`data/works/*.json` 한 단위의 모양:

```json
{ "i": 137, "m": "1092c23",
  "cn": ["[1092c23] 論。三者用大至善因果故…"],
  "ko": ["논의 “셋째는 용대이다”에서…"],
  "nt": ["[구문 불확실] …"] }
```
