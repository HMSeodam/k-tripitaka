# 번역 docx 작성 규격

이 파일을 GPT에 함께 붙여 주시면, 나온 docx를 손대지 않고 그대로
`sources/<문헌id>/번역.docx`에 넣을 수 있습니다.

파서는 **스타일 이름을 신뢰하지 않습니다.** 글자의 종류와 표제의 문구로 판정하므로,
아래 다섯 가지만 지키면 형식이 조금 달라도 읽힙니다.

---

## 1. 원문과 번역을 번갈아 놓습니다

가장 중요한 규칙입니다. 한 문단은 원문 아니면 번역 둘 중 하나여야 하고,
**한 문단 안에 원문과 번역을 섞지 않습니다.**

```
[0287c01] 一釋題目者。大乘有七義故。名為大乘。   ← 원문 문단
첫째, 제목을 해석한다. ‘대승’에는 일곱 가지 뜻이…   ← 번역 문단
[0287c14] 二者頌中敬意者。…                    ← 다음 원문 문단
둘째, 게송 가운데 공경의 뜻이란…                   ← 다음 번역 문단
```

판정 기준은 **한글 비율 12%**입니다. 한글이 거의 없으면 원문, 있으면 번역으로
봅니다. 그래서 번역문 안에 한자를 괄호로 병기하는 것은 얼마든지 괜찮습니다
(`진여(眞如)`, `아뢰야식(阿賴耶識)`). 반대로 원문 문단에 한글 설명을 끼워 넣으면
그 문단 전체가 번역으로 잘못 잡힙니다.

## 2. 위치표지를 원문 앞머리에 남깁니다

```
[0287c01]  ← 네 자리 숫자 + a/b/c + 두 자리 숫자
```

CBETA·SAT·KABC가 공유하는 유일한 좌표라 이걸 기준으로 원문과 번역을 맞춥니다.
**지우지 말아 주세요.** 교감 표지(`[5]`, `[＊]`)도 그대로 두면 화면에서 흐리게 처리됩니다.

위치표지가 없어도 원문 앞머리 열네 글자를 대조해 맞추긴 하지만, 정확도가 떨어집니다.

## 3. 표제로 구조를 알립니다

표제(Word의 제목 1·2·3 스타일)의 **문구**를 보고 네 갈래로 가릅니다.

| 갈래 | 이렇게 쓰면 | 어떻게 처리되나 |
|---|---|---|
| **해제** | `A. 문헌 정보`, `편집·번역 안내`, `핵심 용어표`, `범례`, `검증 보고`, `번역상 쟁점` | 본문에서 빼내 서지 패널로 |
| **권·절** | `권상`, `권하`, `상권 제2분권`, `제3 전역 傳譯第三`, `제1 서왕(序王)` | 분권과 소제목으로 |
| **단위** | `문단 001 · [1089a06]`, `001. T45 0613a08` | 단위 표지로(화면에 안 나옴) |
| **주석** | `주`, `주석`, `각주`, `교감`, `제1문 주` | 이하 문단을 각주 칸으로 |

**해제로 보내고 싶은 것**(편집 방침, 용어표, 검증 보고, 참고문헌)은 위 왼쪽 칸의
낱말을 표제에 넣어 주세요. 그러지 않으면 본문 번역으로 섞여 들어갑니다.

**분권**은 권·절 표제로 잡습니다. 단위가 60개를 넘는 문헌은 자동으로 권 단위로
나뉘어 한 화면에 한 권씩만 나옵니다. `권상/권하`, `상권 제1분권`, `第一序王` 같이
원문의 실제 분권이나 과단을 따르면 가장 자연스럽습니다.

### 단위 라벨은 자동으로 걸러집니다

문단마다 이런 꼬리표를 다는 형식도 그대로 읽힙니다.

```
[1206c22]  문단 001 · 원문     ← 라벨(화면에 안 나옴)
[1206c22] 升高堂者必踐其階…      ← 원문
한국어 직역                     ← 라벨(화면에 안 나옴)
높은 집에 오르는 이는 반드시…     ← 번역
```

위치표지·문단 번호·「원문/번역/직역」 같은 말로만 이루어진 40자 이내의 줄은
라벨로 보고 본문에서 뺍니다. 실제 번역문이 잘못 지워지지 않도록 조건을 좁게 두었으니,
`원문의 서른다섯 논의 항목을…` 같은 문장은 그대로 남습니다.

### 회본은 회본 파일 하나를 원문으로 넣습니다

본문과 주석서를 합친 회본을 번역하셨다면, **번역의 저본이 된 회본 파일 자체**를 원문으로
넣는 것이 가장 정확합니다. 원문은 txt와 docx 둘 다 받습니다.

```
sources/sibimun-jongchi/
├─ 원문.docx      ← 직접 만드신 회본 (한문만 담긴 docx)
└─ 번역.docx      ← 그 회본을 번역한 결과
```

원문 docx에서는 한문 단락만 취하고, 편집 범례·과단 표제 같은 한국어 줄과
`【科層】`·`【科文】`·`【本文】`·`【註】` 같은 편집 표지는 원문 단위로 세지 않습니다.

원문을 여러 파일로 나눠 넣는 것도 됩니다. 파일명 순서대로 이어 붙입니다.

```
├─ 원문-1-십이문론.txt
├─ 원문-2-종치의기.txt
```

다만 번역이 회본 기준으로 되어 있다면 이 방식은 정렬이 어긋나기 쉬우니,
회본 파일 하나를 넣는 편이 낫습니다.

### 이런 형식도 알아서 처리합니다

- **한 문단에 원문 두 대목**이 줄바꿈으로 들어가 있어도 위치표지마다 쪼갭니다
- **번역 한 덩어리가 원문 여러 단락에 걸쳐** 있으면 해당 단락들을 한 단위로 합칩니다
- **問·答이 같은 위치표지를 공유**해도 각각 제 번역을 찾아갑니다

## 4. 각주는 `주` 표제 아래 모읍니다

`주`·`주석`·`각주`라는 줄이 나오면, 그 아래 문단들은 번역이 아니라 각주로 들어갑니다.
**제목 스타일이든 본문 스타일이든 상관없습니다.**

```
주
심지(心地): 마음이 모든 공덕과 현상의 바탕이 된다는 뜻의 비유적 명칭이다.
밀엄국(密嚴國): 여래장·유식 계통에서 불과의 청정한 경계를 가리킨다.
```

다음 한문 원문이 나오면 각주 모드가 풀립니다. 그러니 각주 묶음은 해당 단위의
번역 뒤, 다음 원문 앞에 두세요.

## (참고) 각주는 표제 아래 모읍니다

```
주                        ← Heading 3 정도
삼세·육추: 무명이 일으키는 미세한 세 작용과…
구생·분별: 구생은 태어날 때부터 함께하는…
```

`주` 표제 다음 문단들은 번역이 아니라 각주로 들어가, 화면에서 연둣빛 상자에 담깁니다.
문단 첫머리를 `[구두 불확실]`, `[판독 불확실]`처럼 대괄호로 시작해도 각주로 갑니다.

## 5. 용어 대응표는 표(table)로 만듭니다

첫 줄에 `원어`(또는 `원문`)와 `번역어`(또는 `번역`)가 들어간 두세 칸짜리 표를 두면
자동으로 뽑아 서지 패널의 용어표에 싣습니다.

| 원어 | 번역어 | 비고 |
|---|---|---|
| 眞如 | 진여 | 체·상·용의 체에 해당 |
| 阿賴耶識 | 아뢰야식 | 음역 유지 |

## GPT에 붙일 문구

번역을 시킬 때 이 대목을 그대로 덧붙이시면 됩니다.

> 결과물은 docx로 만들되 다음 형식을 지켜 주세요.
>
> 1. 원문 한 문단, 그 번역 한 문단을 번갈아 배치합니다. 한 문단 안에 원문과
>    번역을 섞지 않습니다.
> 2. 원문 문단 앞머리의 CBETA 위치표지(`[0287c01]` 형태)와 교감 표지(`[5]`)를
>    그대로 남깁니다.
> 3. 원문의 분권·과단(`권상`, `상권 제1분권`, `第一序王` 등)을 제목 스타일로
>    표시합니다.
> 4. 편집 방침·용어표·검증 보고 같은 해제는 `A. 문헌 정보`, `편집·번역 안내`,
>    `핵심 용어표`, `검증 보고`처럼 제목을 붙여 본문과 분리합니다.
> 5. 각주는 `주`라는 제목 아래 모읍니다.
> 6. 용어 대응표는 첫 줄이 `원어 | 번역어 | 비고`인 표로 만듭니다.
> 7. 번역문 안의 한자 병기는 `진여(眞如)`처럼 괄호로 합니다.

## 표제가 없어도 됩니다 (다만 있는 편이 낫습니다)

본문에 분권·과단 표제가 하나도 없는 docx도 읽힙니다. 이 경우 위치표지의
**쪽 번호**가 바뀌는 자리에서 90단위쯤씩 자동으로 끊어, `1206c22–1212c29` 같은
이름의 권으로 나눕니다. 문맥 한가운데가 갈라지지는 않지만, 원문의 실제 분권과는
무관한 기계적 구획이라 표제를 넣어 주시는 편이 읽기에 좋습니다.

권 하나가 150단위를 넘으면 같은 방식으로 더 잘게 나눕니다.

## 넣기 전에 확인하는 법

변환이 제대로 됐는지는 돌려 보면 바로 나옵니다.

```bash
python3 tools/ingest.py
```

출력에서 이 두 가지를 봅니다.

- **번역 대응률**이 90%를 밑돌면 정렬이 어긋난 것입니다. 위치표지가 지워졌거나
  원문·번역이 한 문단에 섞였을 가능성이 큽니다.
- **단위 수**가 원문 문단 수와 크게 다르면 문단 나눔이 어긋난 것입니다.

더 자세히 보려면:

```bash
python3 - <<'EOF'
import json
d = json.load(open('data/works/<문헌id>.json'))
print('단위', len(d['units']), '· 권', len(d['chapters']), '· 해제', len(d['front']))
for u in d['units'][:3]:
    print(u['m'], '|', ' '.join(u['cn'])[:50])
    for k in u['ko'][:2]:
        print('    →', k[:60])
EOF
```

첫 단위의 번역 자리에 편집 안내가 들어가 있으면 3번 규칙을 놓친 것입니다.
