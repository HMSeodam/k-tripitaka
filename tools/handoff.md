# 신한글대장경(k-tripitaka) 작업 인수인계

> 대화창이 바뀌어도 작업을 이어 가기 위한 상태 기록입니다.
> 새 대화창에서는 **최신 저장소 ZIP을 올리고 "tools/handoff.md부터 봐줘"** 라고 하시면 됩니다.
> 세션을 마칠 때 Claude가 이 파일을 갱신해 변경 파일 ZIP에 함께 넣습니다.

마지막 갱신: 2026-09-30 (「계속(6)」 신규 16·5·3·1종 추가 후)

## 0. 반드시 지킬 규칙

1. **기준은 늘 방금 올려 주신 저장소 ZIP입니다.** 이전 대화의 작업 사본을 이어 쓰지 않습니다. 옛 사본으로 작업하면 registry.json의 note가 옛 내용으로 되돌아갑니다.
2. **registry.json의 기존 note는 고치지 않습니다.** 2026-08-23에 100종의 note를 확정했습니다. 새 문헌은 항목만 덧붙입니다.
3. **ZIP에는 그 회차에 바뀐 파일만 넣습니다.** 이미 올린 파일은 다시 주지 않습니다.
4. **규칙은 고치는 문헌에만 적용합니다.** 전체에 거는 규칙은 다른 문헌을 망가뜨린 적이 있습니다(도판 배치 규칙이 석마하연론기·통현초를 깨뜨림, 「저본」 치환이 조사 오류를 냄). 고친 뒤에는 전체 문헌을 다시 변환해 다른 문헌이 바뀌지 않았는지 확인합니다.
5. **韓佛全 책수는 짐작하지 않습니다.** 시대순 추정이 자주 틀리므로 KABC 서지로 확인합니다.
6. **ZIP 파일명은 영문**으로 합니다(다운로드 오류 방지).
7. **화면 파일**(index.html, app.js, app.css)은 선생님이 GitHub에서 직접 고치기도 하므로, 실제로 바꾼 경우에만 넣습니다. app.js나 app.css를 바꾸면 **sw.js의 캐시 버전을 올립니다.**
8. **교감·메모는 읽을 수 있는 한국어로** 보입니다. XML 태그, 파일 경로, orig·lemma·witness 같은 기계용 말은 앱에 나오지 않게 합니다. 긴 교감은 요지 한 줄과 펼침 상세로 나눕니다.
9. **「계속(6)」에서 넣은 원효 문헌 13종은 CBETA에서 가져온 것**이다(출처 CBETA, 장경은 T/X). **『판비량론』은 KABC에서 가져온 것**(한불전, 韓佛全 1책 814c~817a — 선생님이 KABC 서지 화면으로 확인). 『이장의』도 KABC 원문. 다만 선생님 지시로 KABC(한국불교전서) 교감주를 함께 실은 문헌이 있다(열반종요, 보살계본지범요기). 이 메모는 「[KABC 교감]」「[KABC 편집]」 꼬리표와 KABC 출처로 구분해 두며, 오류가 아니므로 지우지 않는다.

## 1. 저장소와 흐름

- 저장소 `HMSeodam/k-tripitaka`, 배포 https://hmseodam.github.io/k-tripitaka/
- 입력: `sources/<id>/원문.txt` + `sources/<id>/번역.docx`
  - 한불전 계열 30종은 `저본.txt`(대조 근거용, 15~16자마다 줄이 끊김)이며 본문은 DOCX 쪽을 씁니다.
  - 1종은 `원문.docx` 형태입니다.
- 변환: `tools/ingest.py` → `data/works/<id>.json`, `tools/rebuild_manifest.py` → `data/manifest.json`
- **GitHub Actions가 push할 때마다 `data/`를 다시 만들어 자동 커밋합니다.** 그래서 `data/`보다 저장소에 올라간 `ingest.py`가 최종 결과를 정합니다. 원본과 도구만 올려도 데이터는 갱신됩니다.
- 전체 변환은 이 작업 환경에서 10분 남짓 걸립니다.
- 점검: `tools/verify.py` → `data/verify-report.json` (원문 대조·번역 공백·교감 공백·도판·제작 메모 잔류)
- DOCX 서식: `tools/번역docx-작성규격.md`. 견본은 **십일면신주심경의소 DOCX(제1호 서식)** 입니다. GPT에는 말로 된 지시보다 견본 DOCX를 직접 주는 편이 안정적입니다.
- DOCX 문단 스타일 다섯 개가 변환의 기준입니다: `SHTK Source Text`, `SHTK Translation Text`, `SHTK Note Summary`, `SHTK Note Detail`, `SHTK Position Marker`.
- 이미지: CBETA 공식 도판은 `cbeta-git/CBR2X-figures`, 교감 ID 대조는 `cbeta-org/xml-p5`를 씁니다. 도판은 `assets/figures/<id>/`에 넣습니다.

### 자료 업데이트 기록 (`data/updates.json`)
- 상단 오른쪽 「업데이트」 버튼이 이 파일을 읽는다. Actions가 다시 만들지 않는 수작업 파일이다.
- **문헌을 추가·수정한 회차마다 맨 위에 항목을 하나 덧붙인다**: `date`(YYYY-MM-DD), `title`(한 줄), `added`/`changed`(문헌 id 목록), `memo`(한두 문장).
- 문헌 화면의 「번역본」 버튼은 `sources/<id>/번역.docx`를 한국어 제목 파일명(예: 구사론기.docx)으로 내려받게 한다. sw.js는 `/sources/` 요청을 캐시하지 않는다.

## 2. 요청하실 때의 형식

```
[신규] CBETA T45n1870
원문 TXT와 번역 DOCX 올림. 분류는 화엄으로.
```
```
[수정] 화엄경탐현기
교감주 표시를 십일면경의소 방식으로 바꾼 최종본. 원문 TXT는 그대로.
```
신규는 CBETA 번호와 분류(collection)를 적어 주시면 좋습니다. 제목·저자·권수·note·ID는 Claude가 CBETA 공식 자료로 조사합니다. 수정은 무엇을 고쳤는지 한 줄 적어 주시면 그 부분을 집중해서 검증합니다.

### GPT DOCX를 받을 때 자주 생기는 일 (「계속(5)」에서 확인)
- **스타일이 통째로 벗겨진 DOCX**(모든 문단이 Normal): 구사론기. 순서(위치표지 → 원문 → 직역 → 「[」 요지 → 「- 」 상세)로 역할을 가려 표준 스타일을 다시 입혔다.
- **문단 안에 칸 이름표 줄**(「원문⏎」「위치표지⏎」「교감·번역 메모⏎」): 구사론소. 위치표지가 0개로 잡히는 원인이 된다.
- **교감 메모 형식이 GPT 회차마다 다름**: 7~20가지 머리표가 섞인다. 공통 칸(교감 번호·저본/이문 독법·번역 영향 판정)을 뼈대로 요지 한 줄 + 상세로 다시 썼다. 요지는 CBETA 원교감식을 우선하고, GPT가 적은 독법 칸은 원교감식이 없을 때만 쓴다(둘이 어긋난 사례가 있었음).
- **상세 한 문단에 교감 여러 건**, **표지만 있는 원문 줄의 중복**(「[7]」「[7]」), **외자 자리에 그림**(원문 글자 누락) — 모두 해당 문헌 DOCX에서만 바로잡았다.
- 이렇게 정리한 DOCX가 저장소의 `번역.docx`로 들어간다(원본 GPT 파일과 다름). 원문·번역 글자는 바꾸지 않았다(외자 그림을 TXT 글자로 되돌린 것, 홍명집 「日燭/王該」 칸 나눔만 예외).

### 「계속(6)」에서 새로 본 GPT DOCX 유형
- **CBETA XML 표제를 제목(Heading 4)으로 넣은 문서**(광홍명집 127곳): 제목 한문이 TXT의 목록 줄과 같아 원문 단위로 한 번 더 서면서 원문이 어긋났다. 제목을 「…」로 감싸 목차 제목으로만 쓰게 했다(ingest.py는 그대로).
- **본문 제목이 「본문 번역」이고 권상·권하가 Heading 1**(지의 보살계의소): 본문이 10단위만 잡혔다. 「본문」으로 고치고 권을 Heading 2로 한 단계씩 내렸다. 교감이 「교감 요약: …」·한 줄씩 「항목: 값」 꼴이라 표준 꼴로 바꿨다.
- **칸 이름표가 Normal 문단**(열반종요 926곳 → 메모로 새어 나옴), **검수 표지가 Block Label/Verification 문단**(법화종요 52곳), **회차 통계가 상세 문단으로 본문 사이에 남음**(지의 6회차분) — 문헌별로 정리.
- **교감 번호 누락**: 제경요집 18건(명본 권 나눔 「卷第六上終【明】」 따위, 「述意前行…十字」 따위), 지의 1건, 대혜도경종요 1건은 CBETA XML 원문으로 메모를 새로 써 넣었다.
- 16종 공통 정리 도구: 작업 폴더의 `normnotes.py`(요지 한 줄 + 상세, 기계용 말·상투 문장·제작 기록 제거, 외자 PUA 코드를 CBETA 외자표의 유니코드·조합식으로 바꿈). 원문·번역 글자는 바꾸지 않았다. 예외: 번역문의 마크다운 백틱(「`…`」 → 「「…」」), 광홍명집 목록 줄 4곳의 번역을 앞 줄과 나눠 채움.

## 4. 회차 기록

### 「계속(6)」 (2026-09-30) — N-gram 하이라이트 창 구간 이동
- `apps/ngram/index.html` 의 「하이라이트 적용」 새 창에만 손댐(분석 기능은 그대로)
- 도구줄에 「∧ n / N ∨」: 이전·다음 하이라이트 구간으로 이동, Enter / Shift+Enter, F3 도 같음. 첫 이동은 지금 보고 있는 자리 다음 구간부터
- 오른쪽 가장자리 세로 띠에 구간마다 빨간 눈금(PDF 뷰어 찾기와 같은 방식). 눈금을 누르면 그 구간으로 감. 현재 구간은 주황 눈금 + 글자 뒤 연노랑 바탕
- 구간 세기: 이어진 빨간 글자를 한 구간으로 보고, 사이에 구두점·공백만 있으면 같은 구간으로 이어 셈. **구두점·숫자·기호는 여전히 칠하지 않음**(칠하는 규칙은 바꾸지 않음)
- 빨간 글자를 누르면 그 구간이 현재 위치가 됨
- HTML로 저장한 파일을 다시 열어도 같은 기능이 동작(눈금 띠는 저장본에 넣지 않고 열 때 새로 그림). Word 저장은 본문만이라 영향 없음
