# 신한글대장경(k-tripitaka) 작업 인수인계

> 대화창이 바뀌어도 작업을 이어 가기 위한 상태 기록입니다.
> 새 대화창에서는 **최신 저장소 ZIP을 올리고 "tools/handoff.md부터 봐줘"** 라고 하시면 됩니다.
> 세션을 마칠 때 Claude가 이 파일을 갱신해 변경 파일 ZIP에 함께 넣습니다.

마지막 갱신: 2026-11-18 (「계속(7)」 권 나눔 정비 후)

## 0. 반드시 지킬 규칙

1. **기준은 늘 방금 올려 주신 저장소 ZIP입니다.** 이전 대화의 작업 사본을 이어 쓰지 않습니다. 옛 사본으로 작업하면 registry.json의 note가 옛 내용으로 되돌아갑니다.
2. **registry.json의 기존 note는 고치지 않습니다.** 2026-08-23에 100종의 note를 확정했습니다. 새 문헌은 항목만 덧붙입니다.
3. **ZIP에는 그 회차에 바뀐 파일만 넣습니다.** 이미 올린 파일은 다시 주지 않습니다.
4. **규칙은 고치는 문헌에만 적용합니다.** 전체에 거는 규칙은 다른 문헌을 망가뜨린 적이 있습니다(도판 배치 규칙이 석마하연론기·통현초를 깨뜨림, 「저본」 치환이 조사 오류를 냄). 고친 뒤에는 전체 문헌을 다시 변환해 다른 문헌이 바뀌지 않았는지 확인합니다.
5. **韓佛全 책수는 짐작하지 않습니다.** 시대순 추정이 자주 틀리므로 KABC 서지로 확인합니다.
6. **ZIP 파일명은 영문**으로 합니다(다운로드 오류 방지).
7. **화면 파일**(index.html, app.js, app.css)은 선생님이 GitHub에서 직접 고치기도 하므로, 실제로 바꾼 경우에만 넣습니다. app.js나 app.css를 바꾸면 **sw.js의 캐시 버전을 올립니다.**
8. **교감·메모는 읽을 수 있는 한국어로** 보입니다. XML 태그, 파일 경로, orig·lemma·witness 같은 기계용 말은 앱에 나오지 않게 합니다. 긴 교감은 요지 한 줄과 펼침 상세로 나눕니다.
9. **「계속(6)」에서 넣은 원효 문헌 13종은 CBETA에서 가져온 것**이다(출처 CBETA, 장경은 T/X). **『판비량론』은 KABC에서 가져온 것**(한불전, 韓佛全 1책 814c~817a — 선생님이 KABC 서지 화면으로 확인). 『이장의』도 KABC 원문. 다만 선생님 지시로 KABC(한국불교전서) 교감주를 함께 실은 문헌이 있다(열반종요, 보살계본지범요기). 이 메모는 「[KABC 교감]」「[KABC 편집]」 꼬리표와 KABC 출처로 구분해 두며, 오류가 아니므로 지우지 않는다.

## 1. 저장소와 흐름

- 저장소 `HMSeodam/k-tripitaka`, 배포 https://hmseodam.github.io/k-tripitaka/
- 입력: `sources/<id>/원문.txt` + `sources/<id>/번역.docx`
  - 한불전 계열 30종은 `저본.txt`(대조 근거용, 15~16자마다 줄이 끊김)이며 본문은 DOCX 쪽을 씁니다.
  - 1종은 `원문.docx` 형태입니다.
- 변환: `tools/ingest.py` → `data/works/<id>.json`, `tools/rebuild_manifest.py` → `data/manifest.json`
- **GitHub Actions가 push할 때마다 `data/`를 다시 만들어 자동 커밋합니다.** 그래서 `data/`보다 저장소에 올라간 `ingest.py`가 최종 결과를 정합니다. 원본과 도구만 올려도 데이터는 갱신됩니다.
- 전체 변환은 이 작업 환경에서 10분 남짓 걸립니다.
- 점검: `tools/verify.py` → `data/verify-report.json` (원문 대조·번역 공백·교감 공백·도판·제작 메모 잔류)
- DOCX 서식: `tools/번역docx-작성규격.md`. 견본은 **십일면신주심경의소 DOCX(제1호 서식)** 입니다. GPT에는 말로 된 지시보다 견본 DOCX를 직접 주는 편이 안정적입니다.
- DOCX 문단 스타일 다섯 개가 변환의 기준입니다: `SHTK Source Text`, `SHTK Translation Text`, `SHTK Note Summary`, `SHTK Note Detail`, `SHTK Position Marker`.
- 이미지: CBETA 공식 도판은 `cbeta-git/CBR2X-figures`, 교감 ID 대조는 `cbeta-org/xml-p5`를 씁니다. 도판은 `assets/figures/<id>/`에 넣습니다.

### 권 나눔과 화면 나눔 (「계속(7)」에서 새로 정함)
- **권(juan)과 화면(chapters)을 따로 저장한다.** 문헌 JSON의 `juan` = 권 목록 `[{t, i, e, cn}]`, `chapters` = 화면 목록 `[{t, i, j}]`(j = 소속 권 번호). N-gram은 `juan`만, 대조 화면은 `chapters`를 쓴다.
- **권의 근거 순서(선생님 결정: CBETA 자료는 원본 XML에서 경계를 가져온다)**
  1. 한불전(KABC): 저본 위치표지의 권차(「卷一 第1張」·「卷上 第3張」·「卷第15」)
  2. **CBETA: 원본 XML(cbeta-org/xml-p5)의 `<cb:juan fun="open">`.** `tools/cbeta_juan.py`가 문헌마다 권 시작 행·권 제목·**첫 본문 14자(lead)**를 `tools/cbeta_juan.json`에 적어 두고, `ingest.py`는 lead를 우리 원문에서 차례로 찾아 그 단위를 권의 시작으로 삼는다(위치표지 쪽 번호는 판본마다 달라 쓰지 않음). 원문에 없는 권(일부 권만 실은 문헌)은 건너뛴다. 찾은 권 사이에 못 찾은 권이 30% 넘게 끼면 이 방법을 버리고 3으로 간다. 못 찾은 권은 3의 원문 표제가 같은 권을 잡았으면 그 자리로 메운다.
  3. 원문 TXT에 남은 권 표제 줄(여는 줄·닫는 줄, `detect_juan`)
  4. 번역 DOCX 제목 가운데 「권」 이름(「권 제二」, 「상권 제1분권」 따위)
- **GitHub Actions가 빌드할 때 `cbeta_juan.py`를 먼저 돌려 표에 없는 문헌만 XML을 받아 온다**(새 CBETA 문헌을 올리면 자동). 표는 `tools/cbeta_juan.json`으로 자동 커밋된다. XML 권 제목 읽기: 마지막 「卷」 뒤를 읽고(「經卷第八疏卷第五末」→권5 말), 「上卷之一」→권상-1, 「上一上」→권상-1 상, 「本末合」→한 권, 번호가 XML 권 번호와 어긋나면 XML 번호를 따르고 제목의 本·末은 버림(「卷第一五科入」→권1, 성유식론학기 「古迹記卷第三本」=XML 1a→권1-1, 1b→권1-2). lead는 두 갈래로 찾는다: 원문 그대로 / 괄호 협주·「(至)」를 뺀 원문(XML은 협주를 `<note>`로 따로 두어 lead에 없음 — 구사론송소기 권2 「言有見者(此云有)…」). 찾은 단위 바로 앞의 권 제목·찬자 줄은 새 권에 붙이되(몇 단위 앞 품 제목 너머에 이 권 표제가 있으면 거기까지), XML 권 제목과 똑같은 줄을 붙였으면 그 앞의 서명만 적힌 줄(앞 권 닫는 줄)에서 멈춘다. lead로도, 원문 권 표제로도 못 잡은 권은 우리 원문의 위치표지가 XML 행 번호와 같은 판본일 때(찾은 권들의 표지가 XML 행과 같은 쪽인지로 판별) XML 권 시작 행 뒤 첫 표지 단위에서 연다(화엄경전기 권5 — `juan_warn`에 「위치표지로 잡음」).
- **권 대신 목차의 편으로 나누는 문헌**: `registry.json` 항목에 `"divisions": [{"t": 이름, "at": 첫머리 글자, "nth": n}]`을 적으면 그것이 가장 먼저다(`juan_from_divisions`). 각 "at"은 그 단위 원문 첫머리(각주 번호 숫자 빼고)가 이 글자로 시작하는 단위를 앞에서부터 찾는다. 첫 항목은 "at" 없이 맨 앞부터. JSON에 `"juan_kind": "divisions"`가 붙고 화면 단추는 「이전·다음」. 2026-11-18 현재 한불전 목차(선생님 스크린샷)대로 3종: 태고화상어록(語錄序·錄序·語錄 上·語錄 下·行狀·塔銘并序·門徒·跋 — 한불전 목차에는 「高麗國國師…」 한 항목이지만 원문에 행장과 탑명이 따로 있어 둘로 나눔), 삼문직지(序·三門直指·乾隆三十四年 刊記), 조계진각국사어록(目次·上堂·示衆·小叅·室中對機·垂代·下火·法語·書答·補遺).
- 권 정보가 없는 나머지 6종(십이문론·종치의기 회본, 범망경술기 돈황본, 영락본업경소, 사분율수현록, 이부종륜론술기, 이장의)은 대부분 1권짜리라 그대로 둔다(선생님 결정).
- 之上·之下·本·末·之一·之餘는 **별도 권**(선생님 결정). 2026-11-18 현재 209종 가운데 CBETA XML 176종, 한불전 張표지 9종, 원문 표제 2종, 권 없음 22종.
- 화면: **1권 = 1화면**. 원문이 2만 5천 자(`SCREEN_CHARS`, 선생님 결정)를 넘는 권만 그 권 안에서 고르게 나눠 「권3 (1/2)」. 권 경계를 넘어 자르지 않는다. 권이 없는 문헌은 2만 5천 자 이하면 한 화면, 넘으면 「1/3 · 품 이름」. 자르는 자리는 절 제목 시작 > 쪽 바뀌는 곳 > 목표 지점 가까운 곳 순.
- 묶음형 번역(한 단위에 원문 여러 쪽)에서 본문 끝에 권 표제 줄이 붙은 단위는 떼어 따로 세운다(`split_juan_titles`). 번역 쪽은 ① 권 표제가 따로 줄을 차지하거나 ② 한 줄에 「…본문. 『書』 권제1 말. 『書』 권제2 본. 아무개 지음. ○편명」 처럼 합쳐져 있어도 원문 덩어리 줄 수에 맞춰 자른다(`split_glued_ko`). 다음 단위들이 번역 없는 짧은 줄(「法語」·「示…」)이면 번역 끝 줄을 한 줄씩 넘긴다. 같은 교감표지 번호를 짚은 메모가 그 단위에 있으면 옮기지 않는다. 한 단위 안에 「앞 권 닫는 표제 / 다음 권 여는 표제 + 본문」이 들고 원문·번역 줄 수가 같으면 여는 표제에서 둘로 나눈다(`mid_juan_split`, 사론현의기 권8/9). 2026-11-18 현재 화엄경소 59곳, 사분율행사초비 30곳, 천목중봉광록 6곳, 기신론의기 1곳, 사론현의기 1곳. 남은 곳: 화엄경소 권45/46(원문 한 줄에 「卷第四十五⏎卷第四十六」이 붙고 품 제목이 둘), 사분율행사초비 목차 끝.
- 반대로 원문 권 표제·찬자·편명 줄이 번역 없는 단위로 따로 섰는데 그 번역이 앞 본문 단위 번역 끝에 한 줄로 붙은 경우(천목 「…(상륜절). 『…』 권 제5 상. 참학 문인 … 올림. 법어(法語). 해인거사에게 보임.」) 잘라서 각 단위에 나눠 준다(`distribute_title_ko`; 천목 30, 홍명집 14, 대혜어록 2, 금강경주 1). 번역의 권 번호가 원문 권 번호와 같을 때만, 서명이 붙은 원문 표제에는 『…』 붙은 번역만.
- 권 첫머리 당기기에서 품 제목(「明法品第十八(入第十八卷經)」)과 본론 권 인용(「論本卷第二十 修所成地」)은 권 표제로 읽지 않는다(화엄경소 권20, 간정기 권14, 구사론소(신태) 권17, 유가론기 4곳).
- 남은 곳(자동으로 못 나눔): 화엄경소 권45/46, 사론현의기 권10 첫머리(권9 닫는 제목·봉진기가 원문 한 줄에 붙음), 교정별록 권12/13(두 제목이 원문 한 줄), 금광명경문구 권2/3, 천목 권30 첫머리 번역. 연의초 권1/2 부근은 번역이 원문보다 한 단위씩 밀려 있음(DOCX 대응 문제).
- 번역 DOCX 표제가 원문 TXT의 권 표제 줄보다 한두 단위 뒤에 걸린 경우(열반경집해 「《대반열반경집해》 권제43」이 권44 둘째 단위에 걸림) 번역이 같은 단위, 또는 번역 없는 같은 번호의 권 표제 줄로 3단위 안에서 당긴다(`snap_sections`).
- 권 판정에서 사람이 볼 곳은 JSON `juan_warn`에 남고 `verify.py`가 「권 나눔 확인」으로 보고한다.

### 자료 업데이트 기록 (`data/updates.json`)
- 상단 오른쪽 「업데이트」 버튼이 이 파일을 읽는다. Actions가 다시 만들지 않는 수작업 파일이다.
- **문헌을 추가·수정한 회차마다 맨 위에 항목을 하나 덧붙인다**: `date`(YYYY-MM-DD), `title`(한 줄), `added`/`changed`(문헌 id 목록), `memo`(한두 문장).
- 문헌 화면의 「번역본」 버튼은 `sources/<id>/번역.docx`를 한국어 제목 파일명(예: 구사론기.docx)으로 내려받게 한다. sw.js는 `/sources/` 요청을 캐시하지 않는다.

## 2. 요청하실 때의 형식

```
[신규] CBETA T45n1870
원문 TXT와 번역 DOCX 올림. 분류는 화엄으로.
```
```
[수정] 화엄경탐현기
교감주 표시를 십일면경의소 방식으로 바꾼 최종본. 원문 TXT는 그대로.
```
신규는 CBETA 번호와 분류(collection)를 적어 주시면 좋습니다. 제목·저자·권수·note·ID는 Claude가 CBETA 공식 자료로 조사합니다. 수정은 무엇을 고쳤는지 한 줄 적어 주시면 그 부분을 집중해서 검증합니다.

### GPT DOCX를 받을 때 자주 생기는 일 (「계속(5)」에서 확인)
- **스타일이 통째로 벗겨진 DOCX**(모든 문단이 Normal): 구사론기. 순서(위치표지 → 원문 → 직역 → 「[」 요지 → 「- 」 상세)로 역할을 가려 표준 스타일을 다시 입혔다.
- **문단 안에 칸 이름표 줄**(「원문⏎」「위치표지⏎」「교감·번역 메모⏎」): 구사론소. 위치표지가 0개로 잡히는 원인이 된다.
- **교감 메모 형식이 GPT 회차마다 다름**: 7~20가지 머리표가 섞인다. 공통 칸(교감 번호·저본/이문 독법·번역 영향 판정)을 뼈대로 요지 한 줄 + 상세로 다시 썼다. 요지는 CBETA 원교감식을 우선하고, GPT가 적은 독법 칸은 원교감식이 없을 때만 쓴다(둘이 어긋난 사례가 있었음).
- **상세 한 문단에 교감 여러 건**, **표지만 있는 원문 줄의 중복**(「[7]」「[7]」), **외자 자리에 그림**(원문 글자 누락) — 모두 해당 문헌 DOCX에서만 바로잡았다.
- 이렇게 정리한 DOCX가 저장소의 `번역.docx`로 들어간다(원본 GPT 파일과 다름). 원문·번역 글자는 바꾸지 않았다(외자 그림을 TXT 글자로 되돌린 것, 홍명집 「日燭/王該」 칸 나눔만 예외).

### 「계속(6)」에서 새로 본 GPT DOCX 유형
- **CBETA XML 표제를 제목(Heading 4)으로 넣은 문서**(광홍명집 127곳): 제목 한문이 TXT의 목록 줄과 같아 원문 단위로 한 번 더 서면서 원문이 어긋났다. 제목을 「…」로 감싸 목차 제목으로만 쓰게 했다(ingest.py는 그대로).
